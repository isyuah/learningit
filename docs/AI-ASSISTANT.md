# 学习助手

课时页内置一个可选的“边学边问”助手。当前实现是纯前端 MVP：学习者在助手设置中填写 OpenAI-compatible 接口、API key 和模型名称，浏览器直接请求该接口；对话和配置保存在当前浏览器的 `localStorage`。回答按 SSE 流式返回，并在界面中渲染为安全的 Markdown。

## 使用

1. 打开任意课程课时页，点击右下角的“学习助手”。
2. 在设置中填写 API URL、模型名称，以及接口需要的 API key；需要时选择思考强度。
3. 直接提问，或从空状态里的问题入口开始。
4. 对话会自动保存，可在历史列表中切换，也可以新建对话。

API URL 可以填写接口根地址，例如 `https://api.openai.com/v1`，也可以填写完整的 `/chat/completions` 地址。请求使用如下兼容格式：

```json
{
  "model": "your-model",
  "messages": [
    { "role": "system", "content": "...课程上下文..." },
    { "role": "user", "content": "...问题..." }
  ],
  "temperature": 0.4,
  "stream": true,
  "reasoning_effort": "medium"
}
```

思考强度选择“自动”时不会发送 `reasoning_effort` 字段，以兼容不支持该参数的普通模型；选择低、中或高时，客户端按 OpenAI-compatible 常见字段发送对应值。接口如果不返回 SSE，客户端仍会尝试解析普通 JSON 响应。

## 上下文策略

每次提问都会动态拼装上下文，不把上下文永久写进对话消息：

- 当前课程：标题、简介、完整课程大纲。
- 当前课时：标题、简介和课时内容，过长时截断。
- 当前阅读位置：根据课时标题的滚动位置识别当前小节。
- 相关课时：根据问题匹配课程大纲，并读取匹配课时的正文，最多带入 3 节。
- 学习者信息：称呼、基础和学习目标，均为可选。

这样做的好处是对话历史保持简洁，页面切换后上下文仍然以当前阅读位置为准；代价是每次请求都会重新发送当前上下文，后续可以按模型上下文窗口加入摘要或向量检索。

## 安全边界

浏览器直连适合个人本地使用或受信任的内网环境，不适合直接把真实生产 API key 暴露给所有访客。`localStorage` 不是密钥保险箱，能访问该站点的脚本都可能读取它；接口还必须允许当前站点的 CORS 请求。

正式部署时建议增加服务端代理：

```text
浏览器 → 自有 /api/ai/chat → 服务端保存密钥并调用模型服务
```

服务端代理应负责鉴权、限流、费用控制、请求日志脱敏、允许的模型/URL 白名单和上下文长度限制。客户端的 `requestAssistantReply` 可以保留为协议适配层，之后把请求目标切换到自有 API 即可。

## 主要代码

- `src/lib/ai-assistant.ts`：设置、对话持久化、上下文拼装、课时检索和请求适配。
- `src/components/learning/study-assistant.tsx`：浮窗、历史对话、设置表单和消息交互。
- `src/pages/lesson.tsx`：注入当前课程、课时、阅读小节和完成进度。
